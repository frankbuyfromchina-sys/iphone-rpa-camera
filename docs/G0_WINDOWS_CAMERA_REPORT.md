## 三、逐项详细核验证据

### 1. 单张图像规格与完整性 (TEST 1)
- 成功取得原生全尺寸 JPEG 图片，文件大小约 `2.09 MB`（2,098,880 字节）。
- 二进制头部/尾部解析：SOI (`0xFFD8`) 与 EOI (`0xFFD9`) 完整合法。
- 解析 SOF0 标记：实际分辨率为 **4032 × 3024**（12MP 满血后置摄像头原生画质）。
- 响应头部包含完整的 `X-Capture-Id` 与 `X-Captured-At`，耗时 `0.734 秒`。

### 2. 连续自动拍照稳定性与真实变动 (TEST 2)
- 连续 20 次请求，间隔 5.0 秒，20 次全部成功，无单次超时或坏图。
- **Capture ID 唯一性**：20 个 Capture ID 全局唯一。
- **画面变动性验证**：所有归档 20 张帧文件的 SHA256 哈希值 **20/20 互不相同**；在测试中段镜头前变动物体时（如第 11 帧 1,978,570 字节、第 15 帧 2,023,655 字节）数据大小与图像特征呈现明显动态变化，证实为后置摄像头即时捕获，绝非静态或缓存图。
- 延迟统计：Min `0.640s`, Max `1.344s`, Avg `0.803s`, p50 `0.750s`, p95 `1.344s`。

### 3. 容灾、异常捕获与状态自愈 (TEST 3)
- **服务停止识别**：当手机 App 停止局域网服务时，Windows 客户端立刻捕获连接积极拒绝（`WinError 10061`），退出码明确为 `1`，记录 `status=error`，未发生卡死或无限重试。
- **错误 Token 拦截**：使用非法 Token 时，服务端准确拦截并返回 `HTTP 403 Forbidden`。
- **旧图防污染**：任何请求失败时，本地既有 `latest.jpg` 保持原样（哈希与修改时间未动），下游 RPA 不会误将历史图判定为新拍照。
- **重启快速自愈**：手机 App 重新点击启动服务后，Windows 发起下一次请求即刻恢复成功，取得新照片（1.90 MB，0.921s），无遗留状态污染。

### 4. 10 秒低频长程运行验证 (TEST 4)
- 持续 5 分钟、每 10 秒一次的 30 次自动化长测。
- 成功率：**30/30 (100%)**，0 次失败，0 次重试。
- 30 个 Capture ID 完全唯一，30 张图片 SHA256 完全独立。
- 延迟极为平稳：Min `0.671s`, Max `0.953s`, Avg `0.778s`, p50 `0.781s`, p95 `0.938s`。
- 未出现 HTTP 429 请求重叠、503 采集超时或内存泄漏。

### 5. Windows 与 Mac 跨平台一致性 (TEST 5)
- Windows 端直接复用 `Host/poll_snapshots.py`，未引入任何平台特化逻辑或分支。
- Python 标准库在 Windows NTFS 与 macOS APFS 下对 `atomic_save`（原子文件替换）均具备相同保证。
- Surface Pro 4 实测 5 连拍全部顺利通过，Windows 10 状态正式由 `NOT_RUN` 转为 `REAL_RUN_PASSED`。
